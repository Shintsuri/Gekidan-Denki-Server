# Gekidan-Denki-Server

[中文](README.md) | [日本語](README.ja.md) | [English](README.en.md)

『ワールドダイスター 夢のステラリウム』（ユメステ）の非公式ローカルサーバーです。C# / ASP.NET Core / PostgreSQL で、クライアントが必要とする API、リアルタイム通信、プレイヤーデータの永続化を実装しています。

> [!WARNING]
> - 本プロジェクトは学習・プロトコル研究・個人テスト目的の非公式プロジェクトです。ゲームの開発元・運営元とは一切関係なく、公式サービスでもありません。
> - 開発途中のため、実装済みの API が完全なゲーム機能を意味するものではありません。一部のランキングや API は仮データです。

## クイックスタート

### 1. 動作要件

- .NET 10 SDK
- PostgreSQL 16（デフォルトの DB 名は `local_game`）
- 使用するクライアントのバージョンに一致し、かつ使用権のある MasterData とローカルアセット
- 本サーバーに接続できるテストクライアントまたはエミュレーター

### 2. データの準備

- クライアントの `mastermemory.db` を展開し、出力した JSON テーブルをサーバー直下の `masterdata-export/tables/` に配置します。
- [`SiriusLocalServer.csproj`](SiriusLocalServer.csproj) は約 60 個のテーブルを `<EmbeddedResource>` として埋め込むため、欠けていると**ビルドできません**。ソースを clone しただけでは動作しない点に注意してください。
- ゲームのアセットディレクトリ（Resources と Addressables）を用意し、次の手順で `.env` にパスを設定します。

### 3. 設定

```powershell
Copy-Item .env.example .env
```

コメントに従って `.env` を編集します。最低限必要な項目は次のとおりです。

| 変数 | 説明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL の接続文字列 |
| `MASTER_DATA_FILE` | `mastermemory.db` のパス |
| `RESOURCES_ROOT` / `ADDRESSABLES_ROOT` | クライアントのアセットディレクトリ |
| `APPLICATION_VERSION` / `ASSET_VERSION` | クライアントとマスターデータに合わせる必要があります |
| `WDS_SKIP_MASTER_OVERLAY` | **必ず `1`**。それ以外だとクライアントの初期化時にマスターデータのパッチが拒否されます |

### 4. ビルドと起動

```powershell
dotnet build -c Release
cd bin\Release\net10.0
$env:REPLAY_MODE='0'
$env:WDS_SKIP_MASTER_OVERLAY='1'
$env:WDS_EXTRA_UNION_KEYS='1'
.\SiriusLocalServer.exe
```

起動後、`http://127.0.0.1:8099/health` が 200 を返せば正常です。

### 5. クライアント接続

クライアントは HTTPS 443 でサーバーと通信し、自己署名証明書（`server.pfx`）を使用します。テスト用クライアント側でこの証明書を信頼するか、自己署名を許可したテストビルドを使用してください。接続に失敗する場合は、まず証明書と `PUBLIC_BASE_URL` を確認してください。

## 実装状況

アカウント周りはログイン、登録、引き継ぎ、アカウント復旧まで通っており、プレイヤーデータ、ホーム、チュートリアル、プロフィールも永続化されています。

公演と稽古は一通り精算できます。スコア検証、評価、ドロップ、経験値、スターランク経験値、デイリー回数とスタミナの消費・回復まで実装済みで、結果画面で止まる問題も修正しました。

育成面では、キャラクターレベル、才能開花、覚醒、スターランク、スキルレベル、カード強化が正常に動作し、関連するマスターデータと消費も公式テーブルに従って処理しています。劇団側は劇団レベルと対応ボーナスの読み取り・計算（サークル支援部分）を実装しています。

イベント側は公式の PT 計算式、累計 PT 報酬（達成した時点で即時付与）、集計期間終了時のランキング報酬を実装しています。スターランク報酬、ミッション、ミッションパス、ログインボーナスも正常に受け取れます。

ガチャは通常池・イベント池の単発、10 連、天井、履歴に対応しています。交換側は交換所、楽譜交換、購入上限のチェックをカバーしていますが、キャラクターピース交換など一部の API は未実装です。

フォトとアルバムは、撮影生成、アルバム編成、レベルアップ、売却、アビリティ変更、観劇記録に対応しています。

演劇リーグとトリプルキャストは参加報酬とランキング精算が利用できますが、クライアント側のランキング表示はまだ固定データです。フレンドとサークルは概ね利用できますが、一部の操作は仮実装のままです。

リアルタイム通信（gRPC）は正常に接続でき、協力公演とフレンド招待の基本フローも動作します。

## 既知の問題と予定

- 演劇リーグ / トリプルキャストのクライアント側ランキングは固定データのまま（報酬は本物、ランキングは仮）；
- キャラクターピース交換やガチャの引き直しなど、クライアントがまだリクエストを送っていない API は実パケットが取れないため、しばらく空実装のまま；
- マスターデータとゲームアセットはリポジトリに含まれないため、各自で用意する必要があります；
- `WDS_SKIP_MASTER_OVERLAY=1` は必須で、overlay に依存する有償パック系の機能は利用できません；
- サーバーは効果が確定している場合のみスコアを再計算し、動的な効果がある場合はクライアントの値を保持して上限チェックのみ行います。

## 技術スタックとディレクトリ構成

- C# / .NET 10、ASP.NET Core、gRPC、PostgreSQL、MessagePack、MasterMemory
- ポート：`8099` HTTP API、`443` HTTP/1.1 + HTTP/2、`8788` gRPC リアルタイム

```
Endpoints/     HTTP ルーティングとプロトコル処理
Services/      アカウント、プレイヤーデータ、サークル、リアルタイム通信
Game/          ルールと精算（公演、稽古、イベント、報酬）
Storage/       データベース構造とマイグレーション
Protocol/      MessagePack、LZ4、リアルタイムプロトコル
Assets/        マスターデータ読み込みとアセット解決
docs/          進捗、リバースエンジニアリング記録
```
